# A50 (SM-A505FN, Android 11, загрузчик ревизии 9): разблокировка и TWRP

Цель: разблокированный загрузчик, TWRP в разделе RECOVERY, бэкапы на ПК.
После этого можно прошивать probe (`docs/a50-bringup.md`, этап 1).

⚠️ Разблокировка **стирает все данные** и навсегда срабатывает Knox
(Samsung Pay, Secure Folder, часть Samsung Health). Вернуть стоковую прошивку
можно, Knox — нет.

## 0. Подготовка (ничего не стирает)

1. Бэкап всего нужного с телефона (Smart Switch / Google / просто скопировать
   по MTP).
2. Вспомнить пароль Google-аккаунта на телефоне: после сброса может
   попросить (защита FRP).
3. Заряд больше 60 %. Кабель — оригинальный или хороший, порт USB — сзади
   корпуса ПК.
4. На ПК (драйверы Samsung уже стоят — телефон определяется):
   - **Odin 3.14.x** — неофициальная утилита Samsung, качать самому с XDA;
   - **стоковая прошивка** `SM-A505FN`, регион `SER`, той же или новее версии,
     что `A505FNPUU9CWB4`. Надёжный способ — **Bifrost** (открытый,
     github.com/zacharee/SamloaderKotlin): качает прямо с серверов Samsung.
     Это страховка: через Odin она возвращает телефон в исходное состояние;
   - **TWRP**: `twrp-3.7.0_11-0-a505f.img` с официального зеркала
     https://dl.twrp.me/a505f/ (страница устройства:
     https://twrp.me/samsung/samsunggalaxya505f.html);
   - **multidisabler** (автор ianmacd, XDA) — проверить, что в описании есть
     A50 и Android 11.
5. `vbmeta.img` с отключённой проверкой уже сгенерирован:
   `E:\iOS-A50\flash\vbmeta.img` (`tools/a50-odin-tar.py vbmeta`).
   Архив для Odin собирается так (TWRP переименовать в `recovery.img`):

   ```sh
   python tools/a50-odin-tar.py tar E:/iOS-A50/flash/twrp-vbmeta.tar E:/iOS-A50/flash/recovery.img E:/iOS-A50/flash/vbmeta.img
   ```

   Получится `twrp-vbmeta.tar.md5` — его и выбирать в Odin.

## 1. Разблокировка загрузчика (стирает всё)

1. Настройки → Параметры разработчика → **Заводская разблокировка (OEM
   unlocking)** → включить, подтвердить. Если пункта нет: подключиться к
   интернету, включить автоматическую дату/время, перезагрузить, проверить
   снова.
2. Выключить телефон. Зажать **Vol+ и Vol−** одновременно и, не отпуская,
   вставить кабель, подключённый к ПК. Появится синий экран-предупреждение.
3. **Долго держать Vol+** → экран «Unlock bootloader?» → **Vol+** —
   подтвердить. Телефон сотрёт данные и перезагрузится (несколько минут).
4. Быстро пройти первичную настройку, **обязательно подключиться к
   интернету** (Wi-Fi). Снова включить параметры разработчика (7 нажатий на
   «Номер сборки») и убедиться, что пункт «Заводская разблокировка» серый и
   пишет, что загрузчик уже разблокирован.
   Без этого Odin может отказать: «Only official released binaries are
   allowed to be flashed» (состояние KG «Prenormal»).

## 2. Установка TWRP

1. Выключить → режим Download (Vol+ и Vol− + кабель) → **коротко Vol+**
   (Continue). На экране проверить: `OEM LOCK: OFF (U)`, `KG STATE` — не
   `Prenormal`.
2. Odin → Options → **снять галочку Auto Reboot**. Кнопка **AP** →
   `twrp-vbmeta.tar.md5`. Больше ничего не выбирать (BL, CP, CSC пустые).
   **Start** → `PASS!`.
3. Сразу в TWRP, минуя Android: держать **Vol− + Power**, пока экран не
   погаснет, и тут же переключиться на **Vol+ + Power** (кабель к ПК
   подключён), держать до логотипа TWRP. Если загрузился Android — стоковое
   рекавери вернулось, повторить шаги 1–3.
4. В TWRP: Wipe → **Format Data** → ввести `yes`. (Данные Android
   зашифрованы, TWRP их не прочитает.)
5. Скопировать multidisabler на телефон (в TWRP работает MTP) → Install →
   выбрать zip → прошить. Он не даёт Android вернуть стоковое рекавери и
   отключает шифрование.
6. Reboot → System. Android загрузится «с нуля».

## 3. Бэкапы (обязательно перед любыми опытами)

В TWRP:

1. Backup → отметить **EFS** (IMEI!) и **Boot** → свайп. Скопировать папку
   `TWRP/BACKUPS` на ПК.
2. Advanced → Terminal:

   ```sh
   dd if=/dev/block/platform/13520000.ufs/by-name/boot of=/sdcard/boot-stock.img
   blockdev --getsize64 /dev/block/platform/13520000.ufs/by-name/boot
   ```

   Скопировать `boot-stock.img` на ПК, записать размер раздела.

Дальше — `docs/a50-bringup.md`, этап 1 (probe).

## Известная проблема: цикл после TWRP на новых прошивках A505FN

Проверено на этом телефоне (прошивка `A505FNPUU9CWB4`): после прошивки
`twrp-vbmeta.tar.md5` и с кнопками, и без них — цикл «логотип →
предупреждение о разблокировке → логотип с красным текстом “not running
Samsung's official software”». По USB за это время телефон не появляется ни
разу (ядро, похоже, вообще не стартует).

XDA, findroid2000, «[GUIDE] Fix A505FN Custom Recovery Boot-loop» (2023-08):
«Samsung released a security patch that stops custom recoveries loading on
A505FN». Решение оттуда:

1. Download → Odin: прошить полную **старую** прошивку `A505FNXXS9CVJ2`
   (та же ревизия загрузчика 9, поэтому откат разрешён): BL, AP, CP и
   **CSC** (не HOME_CSC), Auto Reboot включён.
2. Пройти настройку, интернет, параметры разработчика: «Заводская
   разблокировка» серая — продолжать.
3. Download → Odin: Auto Reboot выключен, AP = TWRP (у нас
   `twrp-vbmeta.tar.md5`) → PASS → Vol− + Power, на чёрном экране сразу
   Vol+ + Power.

`XXS9CVJ2` — европейская сборка, регион (CSC) телефона может смениться с SER
(на этом телефоне `carrierid` остался `SER`).

## Известная проблема: в TWRP 3.7.0_11 a505f не работает USB

Официальный образ оставляет `sys.usb.configfs=0`, а правила для `mtp,adb` у
него нет — ПК не видит телефон ни по adb, ни по MTP (в Download при этом
видит). Исправленный образ: `E:\iOS-A50\flash\twrp-usbfix.tar.md5` (Odin →
AP, Auto Reboot выкл.). В нём USB поднимается через configfs, **только adb**,
MTP нет — файлы передаются через `adb push`/`adb pull`, бэкапы — `dd` в
`/tmp` и `adb pull` (см. `A50_PROGRESS.md`, 2026-11-13).

## Если что-то пошло не так

- Не загружается / bootloop: Vol− + Power ~7 с → сразу Vol+ и Vol− +
  кабель → Download → Odin: BL, AP, CP, **HOME_CSC** из стоковой прошивки
  (HOME_CSC сохраняет данные, CSC — стирает).
- «Only official released binaries…»: загрузить Android, подключиться к
  интернету, подождать, проверить пункт «Заводская разблокировка».
- Режим Download и загрузчик (S-Boot) этими шагами не затрагиваются, поэтому
  телефон всегда можно восстановить через Odin.
